# B 站账号接入 v0.6

本轮完成 B 站账号的第一阶段：扫码网页登录、加密保存会话、登录检查与断开、带登录状态的浏览、关注动态和自主阅读。应用仍固定在 5173。

## 如何连接

1. 打开青屿的「设置 / 连接与偏好」，找到「小屿的 B 站账号」。
2. 点击「扫码连接 B 站」，用 B 站 App 扫码，并在 App 内确认登录。二维码约三分钟失效，可刷新。
3. 若在同一手机上操作，可保存二维码，再用 B 站扫一扫从相册识别。关闭扫码窗口会取消本次连接。
4. 登录后会显示实际账号昵称、UID 和检查时间。可以查看关注动态，或让小屿自己挑几条阅读。
5. 若希望定时探索，在原有「自主冲浪」中开启并设置时段、间隔和次数；同时保持 B 站来源和「自主冲浪时看看关注动态」开启。连接账号不会擅自改动既有冲浪开关。

账号属于小屿使用的社交身份，不会拿账号昵称覆盖用户称呼。可以单独关闭账号浏览、停用关注动态，或断开本机账号。其他平台的浏览上下文不会接收 B 站 Cookie。

## 当前范围

已支持：

- 实际获取 B 站登录二维码、轮询扫码/确认状态、二维码失效与取消。
- 验证登录结果后再保存，重启后恢复；登录失效提示重新扫码。
- 账号昵称、UID、头像与公开主页。
- 仅对 B 站注入已保存的登录状态，并保存合法更新。
- 读取关注动态卡片；由模型按自己的兴趣挑选，再实际读取内容详情、形成感想并留下生活足迹。
- 关注动态没有新内容时，自动回退到 B 站公开兴趣搜索；不会因空列表停止整个探索。
- 沿用现有阅读范围：标题、简介、图文与可见文字，不代表看完视频。

尚未接入：投稿、发布动态、点赞、关注/取关、评论和私信。界面没有假装可用的写入开关，也没有在测试中对外发布任何内容。后续发布和互动需要分别验证能力、取得必要授权后再接入。

这里使用 [B 站官方登录页](https://passport.bilibili.com/login) 的网页登录流程，**不是开放平台 OAuth 应用授权**。官方网页接口可能变化，平台要求验证码或安全验证时仍需用户处理。开放平台发布能力见 [B 站开放平台](https://openhome.bilibili.com/doc)，不把网页登录等同于获得全部官方 API 权限。

## 凭据与边界

- 登录凭据用现有本机 AES-GCM vault 加密后写入 SQLite，不回传页面、不放进聊天模型提示词、不包含在文字备份中。
- 只将账号公开昵称与 UID 作为小屿自己的社交身份提供给聊天，不将其作为用户身份依据。
- 账号 API 请求限定在 B 站官方域名，读取卡片只生成允许范围内的 B 站内容链接。
- 断开账号会删除本机会话并关闭正在使用它的上下文。版本标记阻止旧扫码结果、旧检查或浏览器回写恢复已断开的登录。
- 「清空数据」默认保留连接设置；同时清除连接配置时会一并断开 B 站。断开本机不会退出用户手机上的 B 站 App。

## 验证

- 43 项测试通过，其中新增 12 项账号测试：登录状态变化、加密、重启恢复、二维码过期/取消、并发轮询、失效与网络异常、断开时的竞态、跨平台 Cookie 隔离、动态解析、兴趣选择与足迹、公开身份与模型隔离、HTTP 路由和空动态的公开兴趣回退。
- 类型检查与生产构建通过。
- 六个页面 × 320/390/768/1440 共 24 组布局检查通过。
- 账号卡片和扫码弹窗在四种尺寸下无横向溢出；过期刷新、关闭取消、连接状态、开关、动态列表、探索请求和断开交互通过浏览器检查。
- 用户已在 B 站 App 完成真实扫码确认，实际登录检查通过；更新服务后，保存的会话仍能恢复并通过平台检查。
- 实际关注接口返回成功，原始动态列表为空；这里记录为「没有可读关注动态」，不推断账号没有关注任何人。存在动态卡片时的挑选流程使用隔离夹具验证。
- 实际执行一次「关注动态 → 空列表 → 兴趣搜索」：使用已保存的登录状态读取两条海洋主题视频的标题、简介与可见文字，生成感想并写入生活足迹。任务完成，记录 `sessionUsed=true`；没有声称看完视频，也未进行发布或互动。
- 使用真实登录凭据检查页面状态及文字备份，均未包含会话与 CSRF 凭据；验证过程只输出布尔值和计数，没有记录实际 Cookie。
